These were the fallbacks in the gdh run and why they happened:

struct_fetch_v4 sequential-eval fallback
Cause: _evaluate_jobs runs sequentially when a batch has only 1 job (len(jobs) <= 1), even if workers=8.
Why it triggered:
AF phase had 1 candidate total.
EXP phase had 9 candidates with batch size 8, so the last batch had 1 candidate.
Impact: none on correctness, only execution mode for those batches.
fit_v5 map-origin fallback to (0,0,0)
Cause: map header origin fields were not available in the MRC, and legacy origin array was also unavailable/incomplete.
What happened: _safe_get_origin fell back to (0,0,0).
Impact: usually low if map coordinates are otherwise consistent (nxstart/nystart/nzstart and voxel steps still used), but it means absolute origin came from default.
struct_fetch_v4 PDBe-to-RCSB fallback
Cause: PDBe mapping for UniProt A0R1C2 returned 404 / no mapping.
What happened: code fell back to RCSB search and found 9 PDB candidates.
Impact: expected and useful fallback; allowed experimental candidates to proceed.
testset_qscore_gt cleanup-directory fallback
Cause: _cleanup_workdir tries to remove directories after deleting map/model files, but fitted_models/logs and fitted_models were still non-empty (kept outputs/logs).
Impact: benign; only directory cleanup warning, not a scoring/fitting issue.
No PCA-frame fallback triggered in this run (no map/model PCA construction failure messages).
